# Duty NextGen — інструкції для Claude Code

Цей файл діє для роботи всередині каталогу `nextgen/`. Він написаний так,
щоб залишатися чинним і після виносу цього каталогу в окремий репозиторій
(`DutyNextGen`, через `git subtree split`) — тому нічого тут не посилається
на шляхи поза `nextgen/`, крім явно позначених винятків.

## Мова спілкування

Спілкуємося українською. Усі відповіді, пояснення, коментарі в коді,
Javadoc — українською (виняток: усталені англомовні технічні терміни,
назви класів/методів/пакетів).

## Обов'язкове правило при кожному коміті

Кожен коміт зі зміною коду в `nextgen/` повинен містити також:

1. **`nextgen/CHANGELOG.md`** — новий розділ `## [X.Y.Z] — YYYY-MM-DD`
   (підрозділи `### Додано`, `### Змінено`, `### Виправлено`).
2. **`nextgen/README.md`** — оновлені розділи, що стосуються змінених
   функцій.

Це не опціонально.

## Що це за проєкт

Наступне покоління застарілого Perl CGI + CVS проєкту Duty (планування
чергувань системних адміністраторів + синхронізація з CalDAV). Детальний
опис архітектури — у `nextgen/README.md`.

Ключові рішення, яких слід дотримуватись:

- **Формат даних не змінюється.** Місячні файли графіка лишаються тим самим
  текстовим форматом ([ Names ] / [ Dates ] / [ LastDay0 ] / [ LastDay1 ],
  позначки `D`/`W`/`O`/`I`/`-`), лише в UTF-8 замість KOI8-U. Не переходити
  на JSON/YAML/базу даних без явного запиту користувача — саме
  людинозрозумілість і зручний git-diff цього формату є цінністю, яку
  свідомо зберігаємо.
- **Git — внутрішній, непомітний для користувача журнал.** Команда ніколи
  не працює з git напряму заради редагування графіка (на відміну від
  застарілого CVS-процесу checkout/edit/commit). Кожне збереження через
  веб-інтерфейс застосунок комітить сам, викликаючи `git` як зовнішній
  процес (`ProcessBuilder`), а не бібліотеку (JGit тощо) — для прозорості
  й простоти аудиту.
- **Не чіпати кореневий каталог репозиторію.** Усе, що стосується
  застарілого проєкту (`../Dockerfile`, `../safe/`, `../duty.ukrhub.net/`),
  лишається недоторканим, доки користувач явно не попросить інакше —
  `nextgen/` розробляється незалежно, паралельно з робочою системою.
- **`../safe/duty/cvs/cvsroot/`** — оригінальний CVS-репозиторій із повною
  історією з 2008 року. Це джерело правди для одноразового імпорту історії
  (див. розділ нижче), не для постійної інтеграції.

## Стек і стиль

- Java 21, Spring Boot 3.3, Maven.
- Thymeleaf для серверного рендеру сторінок.
- Без ORM/бази даних: дані — текстові файли, читання й запис — прямий
  файловий I/O.
- Не додавати абстракцій "про запас" (інтерфейси заради інтерфейсів,
  DTO-шари без реальної потреби) — проєкт невеликий, тримати його простим.
- Javadoc лише там, де WHY не очевидний з коду (наприклад, чому саме такий
  алгоритм ротації чергувань).

## Імпорт історії з CVS

Одноразовий імпорт (216 файлів, 638 ревізій, 2008–2026) виконано скриптом,
що для кожної ревізії кожного файлу викликає `co -p -r<rev>` над відповідним
`,v`-файлом з `../safe/duty/cvs/cvsroot/duty/`, перекодовує KOI8-U → UTF-8 і
комітить у git у хронологічному порядку з оригінальними датою/автором.
Мапінг CVS-авторів на git-ідентичності:

- `olden` → Олександр Русских (супроводжував систему з 2008 р.)
- `root` → автоматичні коміти `cvsadd.sh`/`tds.pl` (генерація наступного
  місяця відбувалася в контейнері від імені root)
- `noc` → черговий склад NOC, що редагував графік уручну

Цей імпорт — одноразова дія, повторний запуск не потрібен і не
передбачений (сам скрипт імпорту не є частиною постійного застосунку).
