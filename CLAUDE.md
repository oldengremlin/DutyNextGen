# Duty NextGen — інструкції для Claude Code

Наступне покоління застарілого Perl CGI + CVS проєкту
[Duty](https://github.com/oldengremlin/Duty) (планування чергувань системних
адміністраторів + синхронізація з CalDAV). Виділено в окремий репозиторій
2026-09-03 з каталогу `nextgen/` монорепо `Duty` через `git subtree split`,
зі збереженням повної історії комітів. Детальний опис архітектури — у
`README.md`.

## Мова спілкування

Спілкуємося українською. Усі відповіді, пояснення, коментарі в коді,
Javadoc — українською (виняток: усталені англомовні технічні терміни,
назви класів/методів/пакетів).

## Обов'язкове правило при кожному коміті

Кожен коміт зі зміною коду повинен містити також:

1. **`CHANGELOG.md`** — новий розділ `## [X.Y.Z] — YYYY-MM-DD`
   (підрозділи `### Додано`, `### Змінено`, `### Виправлено`).
2. **`README.md`** — оновлені розділи, що стосуються змінених функцій.

Це не опціонально.

## Ключові рішення, яких слід дотримуватись

- **Формат даних не змінюється.** Місячні файли графіка лишаються тим самим
  текстовим форматом ([ Names ] / [ Dates ] / [ LastDay0 ] / [ LastDay1 ],
  позначки `D`/`W`/`O`/`I`/`-`), лише в UTF-8 замість KOI8-U. Не переходити
  на JSON/YAML/базу даних без явного запиту користувача — саме
  людинозрозумілість і зручний git-diff цього формату є цінністю, яку
  свідомо зберігаємо.
- **Git — внутрішній, непомітний для користувача журнал.** Команда ніколи
  не працює з git напряму заради редагування графіка (на відміну від
  застарілого CVS-процесу checkout/edit/commit). Кожне збереження через
  веб-інтерфейс застосунок комітить сам, викликаючи `git` як зовнішній
  процес (`ProcessBuilder`), а не бібліотеку (JGit тощо) — для прозорості
  й простоти аудиту.
- **Застарілий проєкт (`Duty`) — окремий репозиторій, незалежний
  деплой-цикл.** Нічого тут не посилається на його файли чи шляхи (крім
  довідкових приміток про походження історії, нижче).

## Імпорт історії з CVS (одноразова дія, вже виконана)

Одноразовий імпорт (216 файлів, 638 ревізій, 2008–2026) виконано в монорепо
`Duty` (до виділення цього репозиторію) скриптом `tools/import-cvs-history.pl`,
що для кожної ревізії кожного файлу викликав `co -p -r<rev>` над відповідним
`,v`-файлом з `safe/duty/cvs/cvsroot/duty/` репозиторію `Duty`, перекодовував
KOI8-U → UTF-8 і комітив у git у хронологічному порядку з оригінальними
датою/автором. Мапінг CVS-авторів на git-ідентичності:

- `olden` → Олександр Русских (супроводжував систему з 2008 р.)
- `root` → автоматичні коміти `cvsadd.sh`/`tds.pl` (генерація наступного
  місяця відбувалася в контейнері від імені root)
- `noc` → черговий склад NOC, що редагував графік уручну

Повторний запуск не потрібен і не передбачений (сам скрипт імпорту не є
частиною постійного застосунку).
